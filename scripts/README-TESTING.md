# Testing with Production ZK Verifiers

## ⚠️ Important Update (2026-04-09)

The ZkApiCredits contract now uses **production Groth16 verifiers** that verify real ZK proofs. Mock proofs will be rejected.

## Test Scripts

### Basic Contract Tests (Bash scripts)

These scripts test basic contract functionality but **skip ZK proof verification**:

```bash
# Deploy contract and make deposit
pnpm test:zk

# Individual test scripts:
bash scripts/test-complete-flow.sh       # Deploy + deposit
bash scripts/test-double-spend.sh        # Double-spend detection
bash scripts/test-invalid-proofs.sh      # Invalid proof rejection
```

**Note**: `test-refund-redemption.sh` has been removed from `pnpm test:zk` because it requires real ZK proofs.

### Contract Integration Test

Check that the production verifiers are properly integrated:

```bash
pnpm test:zk:integration
```

This script:
- ✅ Verifies circuit files exist
- ✅ Checks trusted setup keys are present
- ✅ Confirms contract deployment
- ✅ Displays contract state
- ❌ Does NOT generate real proofs (use backend for that)

### Full E2E Tests with Real Proofs

For complete testing with real ZK proof generation and verification:

```bash
# Start the backend
pnpm start:dev

# Run E2E tests (in another terminal)
pnpm test:e2e
```

The E2E tests include:
- ✅ Real Groth16 proof generation via `/proofs/*` endpoints
- ✅ Proof format validation (BN254 field elements)
- ✅ Contract verification with production verifiers
- ✅ Full withdrawal/refund/slashing flows

See [test/proof-generation.e2e-spec.ts](../test/proof-generation.e2e-spec.ts) for examples.

## Proof Generation

### Via Backend API

```bash
# Generate withdrawal proof
curl -X POST http://localhost:3000/proofs/withdrawal \
  -H "Content-Type: application/json" \
  -d '{
    "secretKey": "123...",
    "idCommitment": "0x...",
    "merklePathElements": [...],
    "merklePathIndices": [...],
    "ticketIndex": 0,
    "signalX": 0,
    "merkleRootExpected": "0x..."
  }'

# Returns:
{
  "proof": [1,2,3,4,5,6,7,8],  // uint256[8]
  "publicSignals": [...]        // uint256[6] for withdrawal
}
```

### Via TypeScript (Client-side)

```typescript
import { ProofGenService } from './src/zk-api/proof-gen.service';

const proofGen = new ProofGenService();

const { proof, publicSignals } = await proofGen.generateWithdrawalProof({
  secretKey: '123...',
  idCommitment: '0x...',
  merklePathElements: [...],
  merklePathIndices: [...],
  ticketIndex: 0,
  signalX: 0,
  merkleRootExpected: '0x...'
});

// Use proof and publicSignals with contract
await contract.withdraw(idCommitment, recipient, proof, publicSignals);
```

## Public Signal Formats

Each circuit has a different number of public signals:

### Withdrawal (6 signals)
```
[signalX, merkleRootExpected, nullifier, signalY, idCommitment, merkleRoot]
 input   input                 output     output    output         output
```

### Refund Redemption (5 signals)
```
[signalX, refundValueClaimed, nullifier, signalY, idCommitment]
 input   input                 output     output    output
```

### Double-Spend Slashing (4 signals)
```
[secretKeyClaimed, nullifierExpected, idCommitment, nullifier]
 input             input                output         output
```

## Migration Guide

If you have old tests using mock proofs:

### Before (Mock Proofs - No Longer Works)
```typescript
const mockProof = [1,2,3,4,5,6,7,8];
const mockSignals = [idCommitment, merkleRoot, nullifier, x, y];
await contract.withdraw(idCommitment, recipient, mockProof, mockSignals);
// ❌ Reverts: InvalidProof()
```

### After (Real Proofs)
```typescript
// Option 1: Generate real proof
const { proof, publicSignals } = await proofGenService.generateWithdrawalProof({...});
await contract.withdraw(idCommitment, recipient, proof, publicSignals);
// ✅ Works!

// Option 2: Use mock verifiers for testing
const mockVerifier = await deployMockVerifier();
await contract.setWithdrawalVerifier(mockVerifier.address);
const mockProof = [1,2,3,4,5,6,7,8];
const mockSignals = [0, merkleRoot, 0, 0, idCommitment, merkleRoot]; // Updated format!
await contract.withdraw(idCommitment, recipient, mockProof, mockSignals);
// ✅ Works with mock verifier!
```
